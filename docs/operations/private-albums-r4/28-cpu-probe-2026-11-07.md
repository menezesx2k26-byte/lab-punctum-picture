# R4 — ensaio de CPU no código exato (2026-11-07)

## Propósito e limites
A imagem sintética no binding `IMAGES` já foi comprovada no Worker efêmero (relatório 27). Isto não comprova CPU do produto nem upload real. O G17 continua FAIL e a produção NO_GO até prova de CPU no limite Workers Free de **10 ms por invocação**, sem upgrade pago.

Este commit adiciona ensaio independente para o HTML público `GET /` **sem atualizar o Worker histórico** nem alterar o domínio de produção. Executa-se somente na branch `fix/punctum-albums-r4-completion-20261107` quando o commit contém `[r4-cpu-readonly-qa]`. A execução cria Worker `punctum-r4-cpu-probe-<run-id>` sob o domínio Workers.dev e o remove na mesma rodada. O código, configurações e resultados ficam no próprio repositório / artifact Actions.

Guarda externa exige token aleatório de 256 bits e admite **somente GET /** sem query; POST e todos os endpoints restantes são 404 antes de invocar o app. A configuração efetiva não inclui R2, Images, cron, preview ou rota customizada, e usa somente D1 de QA já existente (ID exato `2e7710f3-dc92-4aeb-976a-5f15d8c5262c`) para renderizar páginas públicas. O Worker de QA histórico e a aplicação real não são implantados ou modificados. Conta Free, inventário total e nome ausente são exigidos antes da criação. Contagens sintéticas D1 antes/depois e exclusão verificada do script efêmero são exigidas no mesmo runner.

A medição requer 36 páginas completas, HTTP200 e leitura GraphQL dos percentis CPU (microssegundos), com resultado condicional somente se p99 <= 10.000 µs e sem erros. Resultados incompletos não são PASS. O relatório **não autoriza publicação** e não substitui testes de upload, acesso humano, LGPD, segurança independente, iOS e rollback.
