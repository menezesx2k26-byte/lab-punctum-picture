## G17 reachability: the devcontainer now matches the gate

The v1 gap was that `r4-codespace-gates.mjs` lists `HOSTINGER_API` and `PUNCTUM_MANAGED_OUTPUT` among G17's `requiredSecrets`, but neither name was in the devcontainer `secrets` block, so the documented Codespaces flow would never prompt for them and G17 would perpetually SKIP. Commit `111340c` adds both as name-only entries with descriptions that point at the exact consumers (`scripts/hostinger_managed_production.py` via `scripts/hostinger_managed_qa.py` for the API token; the export directory for the output path). (confirmed)

A programmatic cross-check of every `GATES[].requiredSecrets` name against the devcontainer secrets keys now reports no missing names across the full union (`CLERK_*`, `CLOUDFLARE_API_TOKEN`, `GITHUB_RUN_ATTEMPT`/`GITHUB_RUN_ID`/`GITHUB_SHA`, `HOSTINGER_API`, `PUNCTUM_*`, `SOURCE_ADMIN_*`). The block parses as strict JSON. With both names present, the owner following §2 will be prompted for them and G17 — and the G18/G23 that consume its `report.json` — can RUN rather than silently SKIP. (confirmed)

## All-SKIP exit path: contract unchanged, ambiguity surfaced

The exit logic is identical to v1: `exitCode = ranFailures > 0 ? 1 : 0`, so an all-SKIP run still exits 0. The fix is purely additive — when `summary.totals.ran === 0`, `main` prints `NOTE: ran=0 means no gate executed; exit 0 here proves nothing...`. The node-test `all-skip run exits 0 and never spawns a child` still asserts exit 0, so the fail-closed contract ("nothing proven, nothing faked") is intact and was correctly not weakened to force a non-zero exit. `CODESPACE-R4-QA.md` §3 now spells out that a meaningful run needs `ran > 0` and that consumers must gate on `summary.totals.ran`/`passed` rather than the exit code alone. A `--local-only` run prints `ran=2 passed=2 failed=0 skipped=6` and exits 0 as expected (the NOTE does not fire there because `ran > 0`). (confirmed)

The residual caveat is unchanged and non-blocking: a downstream workflow that keys off the exit code alone would still misread an all-SKIP run as success. That now contradicts both the printed NOTE and the runbook, so it is a consumer-discipline item, not a harness defect. (possible)

The v2 commit touches only the devcontainer (name-only additions), the runbook, the orchestrator's NOTE, and the embedded v1 review doc — no secret values, no gate promotion, no count inflation. `node --test scripts/qa/r4-codespace-gates.test.mjs` passes 11/11 including the secret-value non-leakage assertion.
